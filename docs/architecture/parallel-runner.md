# 并行执行引擎 —— 并得起、并不串

设计依据：`docs/design.md` §1.2（Event Collector 收集代码 / 测试 / 缺陷 / 依赖 /
运行时五类事件；Budget 含日成本与并发上限）、§3.5A（每个开发任务独立工作空间；
Git Worktree 必选）；`docs/tasks.md` TASK-P2-013（交付物
`orchestration/parallel_runner.py`；验收"① 并发运行数严格受 `max_parallel_agents`
信号量限制；② 并发任务的 Git Worktree 与临时目录完全隔离，互不产生文件冲突；
③ 多任务并发时的 NDJSON 事件流与成本归集互不串扰"）、R-013、R-017、R-045。

> **并行有两个字，两件事。** "并"是**并得起**——同时跑几个，不能超过配置说的
> 那个数；"行"是**并不串**——几个任务同时跑的时候，工作区、事件流、成本三样
> 互不干扰。
>
> **串扰是最难查的一类错。** 单跑一个任务看不出串扰；串扰只在两个任务同时跑
> 的时候才发生，而它一旦发生，已经把两个任务的结果搅在一起了 —— 搅在一起
> 的结果看起来还挺正常。

## 0. 一句话

**"并发跑起来"不等于"并发跑对"。** 这一层做的是**受控**并发：上限从预算里
取，地盘一人一份，事件各写各的文件，账各记各的名下。

## 1. 一个文件，四件事

| 做什么 | 怎么做 | 不做什么 |
| --- | --- | --- |
| 限并发 | `asyncio.Semaphore`，上限取自 `Budget.max_parallel_agents` | 不自己另设一个上限 |
| 分地盘 | 一任务一 worktree、一分支、一临时目录 | 不共用目录 |
| 分事件 | **一任务一个 NDJSON 文件** | 不往一个文件里混着写 |
| 归成本 | 按任务、按会话记；**按币种分桶**归集 | 不把两种币种的数字加在一起 |

**它不落状态。** 与 `orchestration/gates` 同一套做法：算结论、给迁移，写状态的
是调用方。两边都写就会有一边写丢。

## 2. 上限只有一个出处

并发上限取自 `core/policy/budget.py` 的 `Budget.max_parallel_agents`（R-013：
Budget 含日成本与并发上限，可配）。

**为什么不多设一个地方。** 两处各有一个上限时，"现在到底是几"这个问题就永远
答不准 —— 而答不准的上限等于没有上限。所以编排层**不接收**"最大并发"这个
参数，它只接收一份 `Budget`。

```
project.yaml 的 budget:  →  Project.budget  →  Budget.max_parallel_agents  →  Semaphore(3)
```

### 2.1 用 asyncio 而不是 AnyIO

任务书里写的是"基于 AnyIO/TaskGroup"。**这一层用的是 `asyncio.TaskGroup` +
`asyncio.Semaphore`**，理由有两条：

1. **anyio 不是这个仓库的依赖。** 它只是 httpx 的传递依赖（全仓库零个
   `anyio` / `trio` 的 import），而 `pyproject.toml` 不归这一层改 —— 为一个
   引擎去动依赖表，动静比收益大。
2. **标准库已经够了。** Python ≥3.12（`target-version = "py312"`）自带
   `asyncio.TaskGroup` 与 `asyncio.Semaphore`：**一个任务炸了自动取消其余**、
   **异常成组抛出**、**上下文退出时全部收敛**。AnyIO 的 `TaskGroup` 语义与它
   一致，多引一个库换不来更多东西。

### 2.2 上限管的是"同时占着工作区"几个

信号量包住的是**整个任务生命周期** —— 拿工作区、干活、记账、收摊。所以上限
限制的是"同时占着工作区与临时目录"的任务数，也就是真正稀缺的那个资源。

**但工作区的分配本身是串行的。** `git worktree add` 本来就串行化 worktree 的
增删，而"查租约 → 写租约 → 建 worktree"这串动作被打断就可能留下一个"目录
在、租约不在"的工作空间。所以分配走一把锁 + `asyncio.to_thread`：

**git 是阻塞的，不挪出事件循环，整个并发就退化成串行。** 而这时"上限"那句话
仍然成立 —— 只是永远碰不到上限。所以集成测试里既要证明"没超"，也要证明
"真的一起跑过"。

## 3. 三样隔离

### 3.1 工作区：靠结构，不靠约定

| 隔离的东西 | 靠什么隔离 |
| --- | --- |
| 工作区目录 | 一任务一目录，目录名就是 `task_id` |
| 分支 | 一任务一分支 `agent/<task_id>` |
| 临时目录 | 每个任务一个 `mkdtemp`，名字由系统保证唯一 |

**分支冲突在结构上不可能发生** —— 因为 **git 自己就不许一条分支被两个 worktree
同时检出**。一任务一目录一分支这三条同时成立时，"并发跑会不会撞车"这个问题
不需要靠调用方记得别并发来回答。

**路径穿越也是结构上挡住的。** `task_id` 先过 `validate_task_id` 白名单校验才
拿去拼路径与分支名（`harness/workspace/naming.py`）：`../../etc` 建不到仓库外面，
`a/b` 也不会在分支名里多出一段斜杠。**校验失败就报错，不"清洗后继续用"** ——
悄悄改掉一个 ID 比拒绝它更危险。

### 3.2 事件流：一个任务一个文件

**串流在结构上不可能发生** —— 没有任何一个文件装着两个任务的事件。

**出口是按任务发的，不是按会话发的。** 任务拿到 `TaskEventSink` 之后只管喊
`emit`；出口自己盖着 `task_id` 与 `session_id`，**想写别人的事件写不成**。

**但"不会发生"与"发生了能查出来"是两回事。** 所以有 `NdjsonEventStore.audit()`：
每个文件里的事件都带着 `task_id`，某个文件里出现了别的任务的事件，就是串了。
**查得出来，bug 才有地方冒头。**

**五类事件**（design.md §1.2 的那一行）：代码 / 测试 / 缺陷 / 依赖 / 运行时。
分类是为了能按类查 —— "这一轮改了什么"如果只是一串自由文本，查询就变成全文搜。

### 3.3 成本：按币种分桶

**记的是"谁花的"。** 账本按 `task_id` 与 `session_id` 记 —— 两个并行任务的
钱落到同一个会话上，就说不清哪笔是谁的。

**归集按币种分桶。** 两种币种的数字加在一起是个没有意义的数，**而且加出来
仍然像个像样的金额** —— 错得查不出来。

**币种对不上就报错。** 把 CNY 的钱记进 USD 的账户，比记错数字更坏：数字错了
能对账，币种错了对出来的是"另一个项目的钱"。

**失败不等于没花钱。** 任务跑了半个钟头然后炸了，那半个钟头的钱已经花出去了；
把它记成零，账本就比 reality 好看，而账本好看是查不出来的那种错。所以
`ParallelTaskError` 带着已花的钱。

**超预算不是任务失败。** 钱已经花了，活干成了就是干成了；账本记不记得下是
账本的事（`CostAccounting.recorded`）。

## 4. 一个炸了不要紧

**一个任务失败不影响其余任务。** 失败的那个记成 `FAILED`，其余的照跑 ——
并行的意义就在这儿：一个任务炸了就把整批掀了，等于白并行。

**失败要说清是什么错。** "失败"两个字没法行动；`detail` 里是
`RuntimeError: 具体消息`。

**工作空间照样还。** 炸了也要还 —— 否则一次失败就卡死后面的任务。而**收摊
失败不许盖掉任务本身的结论**：工作空间收不干净是运维的事，任务跑成什么样是
另一回事。

**结论按输入的顺序排。** 并行的完成顺序是随机的，而"这次跑的第几个任务失败
了"不该取决于谁跑得快。

## 5. 怎么跑

```bash
# 演示：真的起 git、真的并发跑三个任务（上限 2）
.venv/bin/python scripts/demo_parallel_runner.py

# 单测（34 条）
.venv/bin/python -m pytest tests/unit/orchestration/test_parallel_runner.py -q

# 集成测试：真 git 的 worktree 隔离（15 条）
.venv/bin/python -m pytest tests/integration/test_parallel_runner_workspaces.py -q
```

演示会真的建一个 git 仓库、真的起三个任务，然后演示：

1. **同时跑着的任务从来没有超过 2 个** —— 而也真的跑满了 2 个（碰巧没重叠
   不算数）；
2. **三个任务写同一个文件名，谁也没踩谁** —— 工作区与临时目录都各是各的；
3. **每个事件文件里只有它自己那个任务的事件**；
4. **一个任务炸了，其余两个照跑**。

集成测试里有一条容易漏的：**观察要在任务跑的时候做**。跑完一轮，引擎已经把
工作空间还回去了（目录没了、分支留着 —— 分支才是产出），"跑完之后目录里有
什么"是问不到问题的。

## 6. 边界

- **这一层不落状态。** 与 `orchestration/gates` 同一套做法。
- **这一层不决定谁该跑。** 排期是 `orchestration/dag_scheduler` 的事；这一层
  只管"给你一批任务，你按上限跑"。
- **任务失败不自动重试。** 重试是有界修复那条线的事（`orchestration/repair.py`），
  有次数、成本、时间三重上限 —— 这里不重复实现，也不该重复实现。
- **工作空间跑完就还。** 目录没了，**分支留着** —— 分支是产出。要留着的不是
  目录，是那条分支。
- **端口是同步的。** `WorkspacePort.acquire` 要真的调 git，而 git 是阻塞的；
  挪到线程里是调用方的事（这一层负责挪）。
